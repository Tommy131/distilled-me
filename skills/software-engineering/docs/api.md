# API / 接口设计规范

> software-engineering 子文档（保留原编号 §15）。适用场景：设计对外 API、IPC、接口契约、错误模型。
> 语言无关；HTTP/JSON 与桌面 IPC 规则同构（IPC 把"HTTP 语义"读作"调用语义"）。

## 15. API / 接口设计

### 15.1 资源与命名

- **资源用复数名词**，路径 `kebab-case`；REST 风格不在路径里放动词（动作走 HTTP 方法或显式子资源 `/items/{id}/archive`）。RPC 风格则动词明确（`/search`、`/export`）。
- 字段名全项目统一一种风格（JSON 默认 `snake_case`，个别栈 `camelCase`）——**取一、写进 CLAUDE.md**。
- 布尔用 `bool`，枚举用**字符串字面量**（非数字，便于调试与演进）；可空字段用 `null` 显式表达，不用魔法值。
- URL 中的 ID 用稳定业务键或 UUID；路径参数与查询参数职责清晰（定位资源 vs 过滤/排序）。

### 15.2 幂等（呼应铁律 7）

- `GET` / `PUT` / `DELETE` 天然幂等；**`POST` 写操作 MUST 支持 `Idempotency-Key`**（客户端生成，服务端去重，TTL 明确）。
- 同 key 重放：返回**首次成功结果**（或首次冲突结果），不重复执行副作用。
- 批操作整体幂等：批 key + 子项 key 均可去重；部分失败见 §15.7。

### 15.3 分页与过滤

- **默认游标分页**（keyset / `cursor` + `next_cursor`），避免深 `offset` 漂移；小集合 MAY 用 `offset/limit`。
- 响应必带 `has_more` 或 `next_cursor: null` 终止信号；单页 `limit` 有上限（默认与最大值写进契约）。
- 过滤/排序参数白名单化；禁止把任意 SQL/字段名字符串直接交给查询层。

### 15.4 统一错误包（呼应铁律 6）

- 错误响应统一包：

```json
{
  "code": "2xxxx_validation_failed",
  "message": "Human readable summary",
  "trace_id": "01J…",
  "details": [{ "field": "email", "code": "invalid_format" }]
}
```

- **不把原始异常/堆栈抛过边界**；堆栈只进日志（见 `docs/observability.md`）。
- **错误码分段**（稳定、可程序化判断）：如 `0xxxx` 基础设施 / `1xxxx` 鉴权 / `2xxxx` 输入校验 / `3xxxx` 领域业务 / `4xxxx` 外部依赖。码稳定，`message` 可改。
- HTTP 状态码语义：`2xx` 成功、`4xx` 客户端错（400 校验、401 未认证、403 无权限、404 不存在、409 冲突/幂等）、`5xx` 服务端错 + 日志。
- 输入校验失败返回 `400` + 逐字段 `details`，不笼统 `"invalid"`。

### 15.5 时间与标识

- 时间戳一律 **ISO 8601 / RFC 3339 UTC**（`2026-10-07T00:00:00Z`）；日期与日期时间分开字段。
- 标识用稳定 ID（`uuid` / 业务键），不用自增数字暴露给外部（防枚举与泄漏规模）。

### 15.6 版本化与兼容

- 对外接口带版本前缀（`/api/v2`）或等价头；**加字段/加端点 = 非破坏性（Minor）**，改语义/删字段/改类型 = 破坏性（Major）。
- 破坏性变更走 ADR + CHANGELOG，旧版本保留兼容窗口；弃用期在响应头或文档标明。
- 契约（OpenAPI / JSON Schema / protobuf）进仓库，生成客户端优于手写漂移。

### 15.7 批量与部分失败

- 批量接口返回**逐项结果**（`[{ "id", "ok", "error"? }]`），整体不因单项失败全废。
- 总状态用 `200`（含明细）或 `207`（多状态）；调用方以逐项 `ok` 为准。
- 配合 §5.4 失败隔离：continue-on-fail，结尾统一列失败明细；日志带批 `correlation_id`。

### 15.8 鉴权、限流与安全边界

- 受保护端点经统一鉴权中间件（见 `docs/security.md`）；处理器不各自发明校验。
- 写操作 CSRF / SameSite / 同源策略按客户端类型声明；服务间用机器身份（mTLS / signed token）。
- 限流：按身份 + 路由；超限返回 `429` + `Retry-After`（或错误包等价字段）。
- 输入大小上限（body / 上传）在网关与应用双重约束。

### 15.9 IPC（桌面/本地进程间）

- 同一套契约规则（命名 / 错误包 / 幂等 / 版本）；**契约带 `schemaVersion`**，两端各自 schema 校验。
- 传输序列化（JSON / protobuf / 语言原生）选一种并在 DESIGN 声明；大对象走流 / 句柄，不走消息体。
- 超时与取消可传递；一端取消另一端 MUST 停止副作用或进入可查询的补偿态。

### 15.10 契约检查清单（设计/评审）

- [ ] 命名风格与错误包在 CLAUDE.md / DESIGN 声明
- [ ] 写操作幂等策略明确（键、TTL、重放语义）
- [ ] 分页有终止信号与 limit 上限
- [ ] 错误码稳定、可程序化；无原始异常外泄
- [ ] 时间 UTC；外部 ID 非自增
- [ ] 版本与破坏性变更窗口写明
- [ ] 批量部分失败可区分
- [ ] OpenAPI/Schema 与实现同步（CI 可检更佳）
