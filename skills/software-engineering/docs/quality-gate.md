# 质量门禁清单（Definition of Done）

> software-engineering 子文档（保留原编号 §13）。适用场景：提交/发布前收尾评审。
>
> **可验证性分层**：`CI` = 有脚本/工具可自动判定，应进 CI；`评审` = 目前仅能人工评审（可后续补工具）。门禁通过要求：所有 `CI` 项脚本全绿 + 所有 `评审` 项人工确认。

## 13. 质量门禁清单（Definition of Done）

提交/发布前逐项核对：

- [ ] **构建**通过，**零新增告警**（告警即错误）。〔CI〕
- [ ] **需求可追溯**：新功能对应 FR/NFR 或 DESIGN 章节有记载。〔评审〕
- [ ] **依赖方向**：无反向依赖；领域层零 IO/框架依赖；引擎层未沾 UI。〔评审；可逐步 CI 化：依赖图 lint / 包引用白名单〕
- [ ] **SRP/文件粒度**：单文件单职责，无超大文件（启发式 ~400 行，超长有豁免理由）。〔评审；可 CI 化：行数阈值报告〕
- [ ] **幂等**：写操作前有检测分支；可重跑无副作用。〔评审〕
- [ ] **错误处理**：边界返回显式结果不抛异常；后台线程不崩；坏输入优雅降级。〔评审〕
- [ ] **并发/资源**：跨线程已 marshal；瞬态订阅已退订；无持锁调外部库。〔评审；静态分析可部分覆盖〕
- [ ] **可观测**：关键节点有分级日志 + 结束汇总。〔评审〕
- [ ] **i18n**：新文案多语言齐全，校验脚本通过；外部输出匹配项已标 `// MATCHED:`。〔CI：`python scripts/check_i18n.py <locales> --baseline en`〕
- [ ] **安全**：无凭据入库（secret 扫描）；敏感项默认排除；下载有校验；高危操作有确认；输入有校验。〔secret 扫描 CI + 其余评审〕
- [ ] **测试**：新增逻辑有单测；预提交门禁全过。〔CI〕
- [ ] **文档**：DESIGN/README 同步；**`docs/CHANGELOG.md` 顶部已加版本段落**；版本号已同步（跨产物校验过）。〔CI：`check_version_sync` + CHANGELOG 段落检查〕
- [ ] **文档落盘**：新增文档都在 `docs/` 下（仅 `README*` 与 `CLAUDE.md`/`LICENSE` 等工具置根文件例外）；根目录/源码目录无散装 `.md`。〔CI：`python scripts/check_docs_layout.py .`〕
- [ ] **平台/编码**：换行/编码符合 `.gitattributes`；无硬编码盘符/绝对路径。〔CI：`git diff --check` 等〕
- [ ] **命名**：新命名空间/类型未遮蔽语言/框架根类型。〔评审；可 CI 化：lint 规则〕
- [ ] **分支**：走特性分支，命名空间化；合并门禁满足（A 档个人项目可豁免分支项，见 SKILL.md 规模分级）。〔CI：分支保护规则〕

> 脚本源：本 skill 的 `scripts/`（可拷贝进目标仓库）。`check_docs_layout.py` 可用 `--extra-root-allow` 声明额外根文件例外。
