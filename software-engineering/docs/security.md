# 安全规范

> Engineering Playbook 子文档（保留原编号 §9）。适用场景：安全加固、凭据管理、权限/鉴权设计。
> 吸收 ISO/IEC 27001 思想：机密性、完整性、可用性；AI 相关改动见 `docs/ai-collab.md` §18.3。

## 9. 安全规范

### 9.1 凭据与机密（铁律 5）

- **凭据永不入库**：私钥 / token / 密码 / 连接串中的口令 MUST NOT 进版本库。
- **注入方式**：环境变量、OS 密钥库、CI secrets、部署侧 secret store。
- **仓库只留非敏感**：公钥、无密钥的配置模板、`.env.example`（占位符，无真实值）。
- **私钥生命周期**：设备/环境本地生成；轮换有记录；泄露即作废重发。
- **Secret 扫描**：B 档 MUST 在 CI 启用 secret 扫描（如 `gitleaks` / 平台自带扫描）；命中即失败。

### 9.2 默认排除与脱敏

- 导出 / 同步 / 诊断包按**脱敏清单**过滤；敏感项默认不带。
- 日志中令牌掩码（如 `tok***`）；邮箱/电话等 PII 按项目清单处理（见 `docs/observability.md`）。
- 确需同步机密时走独立安全通道，并在 DESIGN/ADR 记录。

### 9.3 鉴权与授权

- 受保护端点经**鉴权中间件**校验会话/token；业务处理器不各自发明校验。
- **RBAC / 最小权限**：区分普通用户与管理操作；管理操作单独门控。
- 会话：安全 cookie 属性（HttpOnly / Secure / SameSite）或等价移动/桌面安全存储。
- 失效：登出与吊销路径明确；长生命周期 token MUST 可吊销。

### 9.4 输入与输出

- 外部输入（URL、JSON、查询、文件名、上传内容）经**校验中间件/schema** 清洗。
- 保存配置前先做连通性/有效性探测，通过才生效（与幂等铁律一致）。
- 输出编码防注入：HTML/SQL/命令行/路径拼接按栈使用参数化或官方编码 API。
- 上传：类型/大小白名单；存储路径不可由用户任意拼接。

### 9.5 完整性与供应链

- 下载产物 `sha256`（或更强）校验，防污染。
- 依赖锁定（lockfile）；`audit` / `npm audit` / `vulncheck` 等进 CI（见 `docs/architecture.md` §3.4）。
- 已知高危漏洞 MUST 修复或升级后才能合并（B 档）。

### 9.6 权限与高危操作

- **最小权限 + 集中提权**：仅在确需处提权，一次性、可审计。
- **破坏性操作**（重置/清库/批量删除）：多重确认（警告 + 确认短语或二次 UI）；服务端再鉴权。
- AI 不得擅自执行不可逆数据删除/迁移（§18.3）。

### 9.7 传输与存储

- 生产流量 MUST 使用 TLS（或平台等价安全通道）。
- 静态敏感数据加密存储（磁盘密钥由平台/KMS 管理，不进仓库）。
- 备份与日志同样适用脱敏与访问控制。

### 9.8 安全检查清单（评审/合并前）

- [ ] 无凭据/密钥进库；`.env` / 密钥文件在 `.gitignore`
- [ ] CI secret 扫描通过
- [ ] 受保护 API 有统一鉴权；管理操作有额外门控
- [ ] 输入校验与参数化查询/编码到位
- [ ] 下载/产物有完整性校验
- [ ] 依赖审计无未处理高危
- [ ] 高危操作有确认与审计日志
- [ ] 安全相关 AI 改动已经人工复核（§18.3）

### 9.9 事件响应（最小）

发现泄露或疑似入侵时：轮换凭据 → 撤销会话 → 评估影响面 → 记入 ADR/事故记录 → 补回归检测（secret 扫描规则、测试）。不必等完美流程，先止血。
