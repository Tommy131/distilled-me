# API / 接口设计规范

> Engineering Playbook 子文档（保留原编号 §15）。适用场景：设计对外 API、IPC、接口契约、错误模型。
> 语言无关；HTTP/JSON 与桌面 IPC 规则同构（IPC 把"HTTP 语义"读作"调用语义"）。

## 15. API / 接口设计

### 15.1 资源与命名
- **资源用复数名词**，路径 `kebab-case`；REST 风格不在路径里放动词（动作走 HTTP 方法或显式子资源 `/items/{id}/archive`）。RPC 风格则动词明确（`/search`、`/export`）。
- 字段名全项目统一一种风格（JSON 默认 `snake_case`，个别栈 `camelCase`）——**取一、写进 CLAUDE.md**。
- 布尔用 `bool`，枚举用**字符串字面量**（非数字，便于调试与演进）；可空字段用 `null` 显式表达，不用魔法值。

### 15.2 幂等（呼应铁律 7）
- `GET`/`PUT`/`DELETE` 天然幂等；**`POST` 写操作 MUST 支持 `Idempotency-Key`**（客户端生成，服务端去重）。
- 批操作整体幂等：同 key 重放返回首次结果，不重复执行。

### 15.3 分页
- **默认游标分页**（keyset / `cursor` + `next_cursor`），避免深 `offset` 漂移；小集合 MAY 用 `offset/limit`。
- 响应必带 `has_more` 或 `next_cursor: null` 终止信号；单页 `limit` 有上限。

### 15.4 统一错误包（呼应铁律 6）
- 错误响应统一包：`{ "code": "<stable_code>", "message": "<human>", "trace_id": "<id>" }`。**不把原始异常/堆栈抛过边界**。
- **错误码分段**（稳定、可程序化判断）：如 `0xxxx` 基础设施 / `1xxxx` 鉴权 / `2xxxx` 输入校验 / `3xxxx` 领域业务 / `4xxxx` 外部依赖。码稳定，`message` 可改。
- HTTP 状态码语义：200 成功、`4xx` 客户端错（400 校验、401 未认证、403 无权限、404 不存在、409 冲突/幂等）、`5xx` 服务端错 + 日志。
- 输入校验失败返回 `400` + 逐字段错误明细，不笼统"invalid"。

### 15.5 时间与标识
- 时间戳一律 **ISO 8601 / RFC 3339 UTC**（`2026-10-07T00:00:00Z`）；日期与时间戳分开表达。
- 标识用稳定 ID（`uuid`/业务键），不用自增数字暴露给外部。

### 15.6 版本化
- 对外接口带版本前缀（`/api/v2`）；**加字段/加端点 = 非破坏性（Minor）**，改语义/删字段 = 破坏性（Major）。
- 破坏性变更走 ADR + CHANGELOG，旧版本保留兼容窗口。

### 15.7 批量与部分失败
- 批量接口返回**逐项结果**（`[{ id, ok, error? }]`），整体不因单项失败全废；总状态用 `200`（含明细）或 `207`（多状态）。
- 配合 §5.4 失败隔离：continue-on-fail，结尾统一列失败明细。

### 15.8 IPC（桌面/本地进程间）
- 同一套契约规则（命名/错误包/幂等/版本）；**契约带 `schemaVersion`**，两端各自 schema 校验。
- 传输序列化（JSON/protobuf）选一种并在 DESIGN 声明；大对象走流/句柄，不走消息体。
