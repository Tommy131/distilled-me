# 数据驱动 / 配置 与 国际化

> Engineering Playbook 子文档（保留原编号 §6、§7）。适用场景：数据层/配置/schema 设计、国际化多语言。

## 6. 数据驱动 / 配置设计（Declarative Layer）

- **Schema 版本化**：数据/配置文件带 `schemaVersion`，便于演进与迁移。
- **"方式 + 字段"分派模型**：每个条目声明 `type/method` + 该方式所需字段；引擎按它分派到对应 handler。新增一种方式 = 加一个 handler + 文档化字段表（不改既有分支）。
- **检测/执行分离**：每个条目有判据（`detect`）与动作（`apply`）两面，支撑幂等。
- **配置与"是否启用"解耦**：配置常驻仓库，套用时机由 `applyWhen: always | ifInstalled | ask` 决定 —— 没装该功能的机器也带着它的配置，装上即可一键套用。
- **预设可组合**：`extends` + `select`/`deselect`（支持 `@category:x` 批选再逐项增减）。
- **运行期配置单一来源**：一个权威配置文件（`*.json`）+ 环境变量覆盖；敏感项走环境变量/密钥库，不入配置文件。
- **加内容 = 改数据**：新增条目只动数据文件 + i18n 侧车，**不动引擎**。这是声明式是否达标的验收标准。

### 6.5 数据模型演进与迁移策略

- **永不原地改写用户数据**：迁移 = 写新（新 schema 版本）留旧（旧版本可回读），可回滚；"覆盖式"迁移 MUST 先备份。
- **expand / contract 模式**（数据库/持久化层）：
  1. **Expand**：先加（新列可空/带默认、新表），双写；
  2. **Backfill**：旧数据回填到新结构；
  3. **Contract**：确认无旧版本读者后，再删旧字段。
  任何一步失败，旧版本仍能读旧数据 —— **保证旧版本可读新数据、新版本可读旧数据**的过渡窗口。
- **快照版本化**：持久化快照带 `schemaVersion`；加载器按版本分派升级链（`v1→v2→…→latest`），升级函数幂等。
- **迁移脚本可回滚**：每个迁移有 `up`/`down`（或文档化回滚步骤）；破坏性迁移 MUST 在 ADR 记录 + 发布前人工确认（见 §18.3）。
- **迁移与功能解耦**：迁移单独提交/单独发布，不与业务改动混在同一变更里（降低回归面）。

## 7. 国际化（i18n）规范

多语言是基线能力（即便首版只有一种语言，也按可扩展结构搭）：

- **单一译文核心 + 服务化**：一个进程级 `Localizer`/`LocalizationService`，被所有层共享；支持**运行时切换、无需重启**。
- **扁平 `key → text` 映射**（非 ICU/arb 也可，Map 更 git 友好），点分或模块前缀命名键（`settings.title` / `host_monitor.nav_title`）。
- **按 area/module 拆分、加载时合并**；模块可注册自己的译文（`registerModuleTranslations`），用模块前缀防冲突。
- **回退链**：`当前语言 → 默认语言(en) → key 本身`。**缺键显示 key**，让遗漏自曝。
- **格式化用不变文化（InvariantCulture）**：本地化的是*文案*，不是数字/日期策略；位置参数 `{0} {1}`。
- **UI 即时切换**：镜像主题切换机制（动态资源 + 文化变更事件），带参/动态文案走视图模型属性刷新。
- **首启**按系统 UI 语言映射，设置页可切，CLI 用 `--lang`/环境变量。
- **数据层译文走侧车**：清单文案（如条目 `summary`）放 `<data>/i18n/{en,de}.json`（`id → 译文`），与界面文案分离。
- **边界（绝不本地化）**：① 匹配外部工具**本地化输出**的字面量（如某 CLI 的中文 stdout）绝不翻译，加 `// MATCHED:` 注释；② 诊断/审计日志正文固定一种语言作为稳定记录。
- **门禁脚本**：校验**多语言键集一致 + 占位符索引对齐 + 无重复键 + 侧车 id 覆盖**，退出码非零即失败。加文案 = 各语言同步加 key + 跑校验。
