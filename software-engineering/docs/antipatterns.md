# 反模式清单（评审红旗）

> Engineering Playbook 子文档（保留原编号 §17）。适用场景：代码评审快速扫红旗；与正面规范互为镜像。
> 命中任一项 = 评审打回或要求书面豁免。

## 17. 反模式（负例）

| # | 反模式 | 为什么错 | 正确做法 |
|---|---|---|---|
| 1 | **循环内查库/发请求（N+1）** | 延迟随数据量线性爆炸 | 批量取 + 内存关联；游标分页 |
| 2 | **全局可变单例**（核心引擎/后端） | 隐藏耦合、不可并行测、状态泄漏 | 构造注入；单例仅限小型 UI 服务且 DESIGN 声明 |
| 3 | **按类型分目录**（`controllers/`/`models/`/`utils/` 大杂烩） | 一个功能散落多处，改一处动三处 | 按业务域分目录，模块自包含（§3.2） |
| 4 | **`catch {}` 静默吞错** | 故障不可见，排障无抓手 | 记录（含上下文）+ 降级/续跑（§5.4） |
| 5 | **领域层 `new DateTime()` / 读时钟/读配置** | 领域不纯，不可单测、不可重放 | 时间/依赖从上层注入 |
| 6 | **原始异常抛过公共边界** | 泄漏内部结构，调用方无法稳定判断 | 边界返回显式结果/错误包（§15.4，铁律 6） |
| 7 | **UI 直接写 IO / 引擎依赖 UI 框架** | 违反依赖单向，不可 CLI 先行、不可换前端 | UI 只做协议翻译；引擎零 UI 依赖（铁律 1） |
| 8 | **硬编码盘符/绝对路径** | 跨机/跨平台即崩 | 路径变量化 `${Var}` + 正斜杠 API（§5.6） |
| 9 | **机密写进配置文件/提交** | 凭据入库 = 安全事故 | 环境变量/密钥库注入（铁律 5，§9） |
| 10 | **改稳定核心来加功能**（外科手术式） | 违反 OCP，回归面扩大 | 加模块 + 注册一行 + 数据文件（铁律 2，§3.2） |
| 11 | **持锁调用第三方库/自身回调** | 死锁风险 | 加锁→拷贝句柄→解锁→再调（§5.5） |
| 12 | **列表行各自订阅全局事件** | 高频刷屏 + 泄漏 | 父级统一刷新；瞬态对象显式退订（§5.5） |
| 13 | **一个项目混两套命名/换行** | 检索困难、diff 噪音 | 按栈取一、项目内统一，写进 CLAUDE.md |
| 14 | **翻译 `// MATCHED:` 外部工具本地化输出** | 匹配失效 = 功能静默坏 | 绝不翻译，保留 `// MATCHED:` 标记（§7） |
| 15 | **版本号散落多处且无同步校验** | 产物版本不一致难排查 | 单一版本源 + CI `check_version_sync`（§11.1） |
| 16 | **原地改写用户数据/存量数据** | 不可回滚，一次坏迁移毁全部 | 写新留旧、迁移可回滚（§6.5） |
| 17 | **猜测式"优化"**（未剖析先改） | 可能优化错热点、引入回归 | 先剖析定位热点再改（§5.7） |
